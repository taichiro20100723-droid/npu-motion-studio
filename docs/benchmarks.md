## V4 A→B 統合試験

| モードと内容 | NPU途中画像 | Arc GPU補間 | MP4 | 合計 |

先頭=A、最終=Bの固定はH.264復号後に確認しました。元PNGに対して先頭PSNR 44.15dB、
最終PSNR 41.76dBで、差は主にH.264圧縮です。A/B間のNPU promptは入力した日本語を
ローカル英訳し、`action=run` のような動作分類と進捗率を各中間画像へ付加します。

ロボット→犬はv0.4.1のendpoint-adaptive strengthと変身優先の動作分類で測定しました。
完全に異なる物体なので中間形はシュールになりますが、後半3区間で犬へ明確に収束し、
最終フレームは指定したB画像へ固定されました。

## v0.5 Fast Preview → Quality Upgrade

測定日: 2026-08-22。同じロボット→犬、4秒、ウォーム状態です。

| 段階 | NPU画像 | 補間 | MP4 | 合計 |
|---|---:|---:|---:|---:|
| 4枚プレビュー | 2.36秒 | 0.02秒 軽量補間 | 0.46秒 QSV | **2.83秒** |
| 12枚へ高品質化 | 15.46秒 | 8.23秒 Arc RIFE仕事 | 0.49秒 QSV | **18.05秒** |

12枚版はNPU生成とArc RIFEを区間単位で重ねたため、NPU終了後のGPU待ちは1.57秒でした。
直列なら加算されるGPU仕事の多くをNPU生成の裏側へ隠しています。4枚版はRIFEを3回起動する
オーバーヘッドを避け、まず内容を判断するための軽量補間に切り替えました。高品質化では
8・12・16・20・24枚を選択できます。

Arc GPUの出力で `Intel(R) Arc(TM) 140V GPU (16GB)` が選ばれたことを確認しました。
最終版はH.264もIntel Quick Syncで書き出します。上表のfun/wow 3試験だけは切替前の
libx264値で、最終fast試験はQuick Syncを含む統合値です。
ダンスのループ動画は95フレームで、先頭と末尾の平均画素差1.427に対し、通常隣接フレームの
中央値は2.068でした。2560×1600入力が512×320のMP4になり、元画像比率も維持されました。

以下はV1の履歴です。

## NPU画像生成

モデルは `OpenVINO/LCM_Dreamshaper_v7-int8-ov`。512×512、4 inference steps、
guidance scale 1.0、CPU text encoder / NPU UNet / GPU VAEです。

| 内容 | 実測 |
|---|---:|
| 初回コンパイル | 156.19秒 |
| ウォーム1枚目 | 1.1707秒 |
| ウォーム2枚目 | 1.0457秒 |
| キャッシュ読込後のコンパイル | 5.01〜6.99秒 |

NPUキャッシュだけを有効化しています。GPU VAEのcompiled-model cacheは、今回の
ドライバーとoneDNNの組み合わせで再読込エラーが起きたため無効化しました。

## FlowCacheアンカー

最初のtxt2imgを1枚、前アンカーを変形した低strength img2imgを2枚生成しました。

| strength | 3 anchors合計 | 備考 |
|---|---:|---|
| 0.25 | 3.4371秒 | 顔・色・構図の一貫性が高い |
| 0.35 | 6.1574秒 | 動きは強いが変形と待ち時間が増える |

## 動き補間とMP4

512×512の3 anchorsを、OpenCV DISの前後flowとcycle confidenceで48 framesへ補間し、
16fps、3秒のH.264へ書き出しました。

| 段階 | 実測 |
|---|---:|
| forward/backward flow | 0.0676秒 |
| 双方向補間 | 2.0678秒 |
| libx264 ultrafast encode | 0.1548秒 |
| 合計 | 2.2902秒 |

低信頼領域を0で埋めると黒い穴が出たため、最終実装は信頼度付き補間と通常ブレンドを
画素単位で切り替えます。

## アプリ統合試験

FastAPIへ日本語prompt、`fun`、3秒をPOSTし、NPU pipeline常駐後に完成した値です。

| 項目 | 実測 |
|---|---:|
| NPU画像3 anchors | 5.71秒 |
| flow | 0.11秒 |
| 補間 | 1.95秒 |
| MP4 encode | 0.08秒 |
| エンジン合計 | 7.859秒 |
| API送信から完了確認 | 8.091秒 |

その後、初回MP4 encoderを生成前に暖機し、残り時間の見積りを厳しくしました。最終の
締切制御版は `fun` 3秒・2 anchorsが6.406秒、`wow` 3秒・2 anchorsが4.984秒でした。
どちらもNPU img2imgで2時点を描いており、単一画像の奥行き移動ではありません。

異なるpromptや発熱状態を含むp90/p95の保証値ではありません。公開版の性能表示には、
30入力×3回と10回連続生成の再測定が必要です。
